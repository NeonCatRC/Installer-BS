# Installer-BS GUI — автономный лаунчер, упакованный в `.bs`

Front-end для `bs`, который сам поставляется как `.bs`-пакет. Юзер не клонит репо: качает один файл,
запускает — и получает меню управления своими Installer-BS-пакетами.

Это намеренный контр-экспонат к «враждебному терминалу» оригинала (Музей, Зал 6: форс-ресайз окна,
`read`-пауза после каждого шага, `Terminal=true`). Здесь UI — **опциональный сахар** над полностью
скриптуемым CLI: он зовёт встроенный `bs`, показывает, что делает, и не трогает геометрию терминала.

## Что умеет

- **Установленные пакеты** → выбрать → Запустить / Информация / Удалить (с подтверждением).
- **Открыть `.bs`-файл** → Запустить портативно / Установить / Проверить подпись / Информация.
- Управляющие операции показывают **лог** (честно, без «магии за кадром»).

## Автономность: ядро — чистый bash-TUI, zenity — опция

Ядро интерфейса — **текстовое меню на чистом bash** (нумерованный выбор, ANSI). **Ноль внешних
зависимостей**: работает везде, где есть bash — Ubuntu 16.04, BSD, rescue-shell. Если у хоста есть
`zenity` **и** дисплей — рисуем оконный GUI вместо текста. Итог: лаунчер **никогда не показывает
пустоту**.

Поведение по окружению:

| Условие | Что показываем |
|---|---|
| есть `$DISPLAY`/Wayland **и** `zenity` | оконный GUI (zenity) |
| есть терминал (tty) | bash-TUI (текстовое меню) |
| ни zenity, ни tty (двойной клик в файловом менеджере) | **переоткрываем себя в терминале** (`x-terminal-emulator`…); если терминала нет — `notify-send`/`xmessage` с подсказкой |

Почему не бандлим GUI: `zenity`/`yad` — это GTK; завернуть его релоцируемым **и** совместимым вниз
до Debian 9 — отдельный проект (`linuxdeploy-plugin-gtk`-класса), ~50–80 МБ ради списка. Это ровно
тот «вбандлил браузер ради меню», над которым мы смеёмся. Поэтому: zenity берём у хоста, если есть,
а автономность держит bash-TUI, которому не нужно вообще ничего.

## Сборка

```sh
./bs make examples/bs-gui/recipe
#   ok  built installer-bs-gui-0.3.0-any.bs   (~40 KiB)
```

Payload — это сам **bs-рантайм** (`bs` + `lib/` + `locales/` + `template/`) плюс UI-скрипт. Пакет
**архитектурно-независим**: `arch=any` (в нагрузке нет ни одного ELF, поэтому рантайм-страж арх
пропускает проверку; поле `os` остаётся). Это честная возможность формата — «payload не зависит от
архитектуры», а не костыль.

## Запуск

```sh
./installer-bs-gui-0.3.0-any.bs            # портативно — меню (GUI если есть zenity, иначе TUI)
./installer-bs-gui-0.3.0-any.bs --install  # пункт меню «Installer-BS» (XDG); --uninstall снимет
```

Требования: `bash` + `coreutils` (как у всех `.bs`). `zenity` — **опционально**, только ради окна.

## Проверено (Docker)

- `shellcheck` чисто (лаунчер в lint-наборе проекта);
- сборка `~40 KiB`, `--info` → `linux/any`;
- **bash-TUI прогнан через псевдотерминал**: меню рисуется, Информация и Удаление (с подтверждением)
  отрабатывают, после удаления реестр пуст;
- двойной-клик без zenity/терминала → не «пустота», а попытка переоткрыть терминал (или подсказка);
- e2e самого лаунчера: `--install` (ярлык + `.desktop` + SVG-иконка в `hicolor/scalable`) → `--uninstall` начисто;
- штатные `tests/lint.sh` и `tests/e2e.sh` (**62/0**) — зелёные с правкой `arch=any`.

## Дальше (заложено в архитектуру)

UI вынесен в примитивы `ui_menu`/`ui_confirm`/`ui_run_log`/`ui_pick_*` с двумя реализациями
(zenity / bash-TUI) за одним кодом логики. Добавить **сборку из рецепта с логами** (`bs make`/`sign`
в окне) — это дописать пункт и `ui_run_log`, без переделки. Пока — менеджер пакетов, как договорились.
