# Installer-BS GUI — лаунчер, упакованный в `.bs`

Маленький **GUI поверх `bs`**, который сам поставляется как `.bs`-пакет. Юзер не клонит репо: качает
один файл, запускает — и получает окно для управления своими Installer-BS-пакетами.

Это намеренный контр-экспонат к «враждебному терминалу» оригинала (Музей, Зал 6: форс-ресайз окна,
`read`-пауза после каждого шага, `Terminal=true`). Здесь GUI — **опциональный сахар** над полностью
скриптуемым CLI: он зовёт встроенный `bs`, показывает, что делает, и не трогает геометрию терминала.

## Что умеет

- **Установленные пакеты** → выбрать → Запустить / Информация / Удалить (с подтверждением).
- **Открыть `.bs`-файл** → Запустить портативно / Установить / Проверить подпись / Информация.
- Управляющие операции показывают **живой лог** в окне (честно, без «магии за кадром»).

## Бэкенд: хостовый zenity (ничего не бандлим)

Рисуем диалоги через `zenity` хоста — и осознанно **не вкладываем GTK**. Завернуть весь GTK-стек
(~50–80 МБ) ради списка — это ровно тот «вбандлил браузер ради меню», над которым мы смеёмся. zenity
есть почти везде (GNOME ставит его штатно), стабилен по CLI и совместим **вниз до Debian 9** — потому
что это zenity *хоста* под glibc *хоста*, а не наш бандл.

Нет дисплея или нет zenity → лаунчер **прямо говорит об этом** и отдаёт тот же `bs` в CLI. Это
страж, как проверки арх/glibc, а не второй UI-движок.

> Почему не yad? Он богаче (одно окно, вкладки, лог-панель), но тащит тот же GTK-стек, а собрать его
> релоцируемым **и** совместимым до Debian 9 — отдельный проект (`linuxdeploy-plugin-gtk`-класса).
> Цена не стоит свеч для демонстрационного лаунчера. См. историю решения в коммитах.

## Сборка

```sh
./bs make examples/bs-gui/recipe
#   ok  built installer-bs-gui-0.3.0-any.bs   (~40 KiB)
```

Payload — это сам **bs-рантайм** (`bs` + `lib/` + `locales/` + `template/`) плюс GUI-скрипт. Пакет
**архитектурно-независим**: `arch=any` (в нагрузке нет ни одного ELF, поэтому рантайм-страж арх
пропускает проверку; поле `os` остаётся). Это новая честная возможность формата — «payload не зависит
от архитектуры», а не костыль.

## Запуск

```sh
./installer-bs-gui-0.3.0-any.bs            # портативно — откроется GUI
./installer-bs-gui-0.3.0-any.bs --install  # пункт меню «Installer-BS» (XDG); --uninstall снимет
```

Требования: `bash` + `coreutils` (как у всех `.bs`) и `zenity` для GUI. Без `zenity`/дисплея —
работает как CLI-обёртка.

## Проверено (Docker, ubuntu:24.04)

- `shellcheck` чисто; сборка `40 KiB`, `--info` показывает `linux/any`;
- режим без дисплея → корректный фолбэк в `bs` CLI (встроенный рантайм работает);
- `zenity` рисует под `xvfb`;
- e2e самого лаунчера: `--install` (ярлык + `.desktop` + SVG-иконка в `hicolor/scalable`) → `--uninstall` начисто;
- штатные `tests/lint.sh` (его 0.11.0) и `tests/e2e.sh` (**62/0**) — зелёные с правкой `arch=any`.
