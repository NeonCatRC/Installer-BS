# Installer-BS Manager — автономный лаунчер, упакованный в `.bs`

Front-end для `bs`, который сам поставляется как `.bs`-пакет. Юзер не клонит репо: качает один файл
со страницы Releases, запускает — и получает меню управления своими Installer-BS-пакетами.

Это намеренный контр-экспонат к «враждебному терминалу» оригинала (Музей, Зал 6: форс-ресайз окна,
`read`-пауза после каждого шага). Здесь UI — **опциональный сахар** над полностью скриптуемым CLI: он
зовёт встроенный `bs`, показывает, что делает, и не трогает геометрию терминала. Это честный
терминальный апп, поэтому `Terminal=true` в `.desktop` — по делу (в отличие от оригинала, который ставил
это на оконное приложение).

## Что умеет

- **Установленные пакеты** → выбрать → Запустить / Информация / Удалить (с подтверждением).
- **Открыть `.bs`-файл** → Запустить / Установить (с предупреждением о смене версии) / Проверить подпись / Подписать / Информация.
- **Собрать `.bs` из рецепта** → выбрать рецепт → `bs make` с живым логом.
- **Кэши** → показать / очистить распаковки и скачки (`bs cache`).
- **Информация** — дружелюбная карточка (Название / Описание / Версия / Платформа / Путь / Размер), не сырые ключи.
- Списки с **навигацией стрелками** и **фильтром `/`** (печатай — список сужается; работает и в файловом браузере).
- **Файловый браузер**: навигация по каталогам, выбор `.bs` (вместо ввода пути).
- Управляющие операции показывают **лог** (честно, без «магии за кадром»).
- `installer-bs-gui --help` / `--version` — ведёт себя как нормальная утилита.

## Автономность: самопальный TUI на чистом bash

UI — **текстовый, на чистом bash. Ноль внешних зависимостей**: работает везде, где есть bash — Ubuntu
16.04, BSD, rescue-shell. Никакого zenity/GTK — оконный тулкит ради меню мы не тащим (это был бы свой
Зал музея). Итог: лаунчер **никогда не показывает пустоту** и ничего не требует от хоста.

TUI двухуровневый — по способностям терминала:

- **rich** (по умолчанию на нормальном терминале) — самопальный «dialog» на чистом bash: рамка во весь
  экран, навигация стрелками, выбор инверсией строки, прокручиваемые списки со счётчиком `i/N` и
  полосой прокрутки, живой ресайз по **SIGWINCH**. Дисплей-ширина строки считается в **кодпойнтах**
  (UTF-8 разбираем руками), поэтому кириллица не разъезжает правый край рамки. Уважает `NO_COLOR`,
  рисует в alt-screen (не сорит в скроллбэк) и **гарантированно восстанавливает терминал** на выходе
  и по Ctrl-C (`stty`/курсор/rmcup через trap на EXIT/INT/TERM/HUP).
- **plain** (фолбэк) — нумерованное меню. Включается, когда терминал не умеет адресацию курсора
  (`TERM=dumb`, нет `tput`, нет управляющего tty) или принудительно через `BS_GUI_PLAIN=1`. Никогда
  не удаляется: это «работает всегда»-вариант для дикого окружения.

Мышь — намеренно нет (в bash дорого и хрупко); вся навигация с клавиатуры.

Поведение по окружению:

| Условие | Что показываем |
|---|---|
| терминал с адресацией курсора (`tput`, `TERM≠dumb`) | **rich** TUI (рамка, стрелки, скролл, ресайз) |
| «дикий» терминал / нет `tput` / `BS_GUI_PLAIN=1` | **plain** TUI (нумерованное меню, фолбэк) |
| нет tty (двойной клик в файловом менеджере) | **переоткрываем себя в терминале** (`x-terminal-emulator`…); если терминала нет — `notify-send`/`xmessage` с подсказкой |

Почему не бандлим GUI-тулкит: `zenity`/`yad` — это GTK; завернуть его релоцируемым **и** совместимым
вниз до Debian 9 — отдельный проект (`linuxdeploy-plugin-gtk`-класса), ~50–80 МБ ради списка. Это ровно
тот «вбандлил браузер ради меню», над которым мы смеёмся. TUI самодостаточен, и окна для менеджера
пакетов не требуется.

## Сборка

```sh
./bs make apps/installer-bs-gui/recipe
#   ok  built installer-bs-gui-0.4.0-any.bs   (~48 KiB)
```

Payload — это сам **bs-рантайм** (`bs` + `lib/` + `locales/` + `template/`) плюс UI-скрипт. Пакет
**архитектурно-независим**: `arch=any` (в нагрузке нет ни одного ELF, поэтому рантайм-страж арх
пропускает проверку; поле `os` остаётся). Это честная возможность формата — «payload не зависит от
архитектуры», а не костыль.

## Распространение

Готовый `.bs` публикуется отдельным **GitHub-релизом** (`bs-gui-X.Y`, ассеты `.bs` + `.sha256` +
`.sig`) — пользователь качает один файл, без клонирования репо. Релиз иммутабелен и несёт ровно ту
версию `bs`+формата, что была в дереве на момент тега (провенанс = тег).

## Запуск

```sh
./installer-bs-gui-0.4.0-any.bs            # портативно — открывает меню в терминале
./installer-bs-gui-0.4.0-any.bs --install  # пункт меню «Installer-BS Manager» (XDG); --uninstall снимет
```

Требования: `bash` + `coreutils` (как у всех `.bs`). Больше ничего.

## Проверено (Docker, `ubuntu:24.04` + `python3` для pty)

- `shellcheck` чисто на лаунчере (он в lint-наборе проекта);
- сборка `~48 KiB`, `--info` → `linux/any`;
- **rich TUI прогнан через псевдотерминал** (матрица): навигация стрелками и подсветка выбора;
  длинный список — скролл, счётчик `i/N`, полоса `▲┃▼`; `ui_confirm` (←→, дефолт «Нет»); `ui_run_log`
  (`bs info` живьём + `[exit 0]`); `ui_pick_file` (ввод пути через `read -e`); **живой ресайз**
  (SIGWINCH) без артефактов; `NO_COLOR` (выбор маркером, рамка ровная); **терминал восстановлен после
  выхода** (smcup/rmcup, курсор, `stty`);
- **plain-фолбэк** (`BS_GUI_PLAIN=1`) — нумерованное меню рисуется как раньше;
- двойной-клик без терминала → не «пустота», а попытка переоткрыть терминал (или подсказка);
- e2e самого лаунчера: `--install` (ярлык + `.desktop` + SVG-иконка в `hicolor/scalable/apps/installer-bs-gui.svg`) → `--uninstall` начисто;
- штатные `tests/lint.sh` (shellcheck, `lint ok`) и `tests/e2e.sh` (**62/0**) — зелёные.

## Локализация

Строки UI вынесены в **бандл-локали** `app/locale/<lang>.sh` (ассоциативный массив `GUI_STR`),
которые пакуются в `.bs`. Язык берётся из `$LANG`; `en` — фолбэк-база, язык накладывается поверх
(частичный перевод докатывается английским по ключу). **Добавить язык = доложить файл** `app/locale/<lang>.sh`,
правка кода не нужна. Подписи карточки Info (Название/Описание/…) тоже локализованы (значения — это
метаданные пакета, их не трогаем).
