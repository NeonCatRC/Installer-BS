# Гайдлайны Installer-BS (код + сатира)

Обязательно к прочтению любым агентом перед коммитом. Цель: ноль AI-флагов, ноль говнокода,
едкий но точный тон.

---

## 1. Bash — стиль

- Шебанг: `#!/usr/bin/env bash`. Библиотеки (`lib/*.sh`) — без шебанга, только `source`.
- В исполняемых скриптах: `set -euo pipefail`. Где `pipefail` мешает (опрос `type`/`ldd`) —
  локально и осознанно отключать, с комментарием почему.
- Имена функций: `lower_snake_case`. **Запрещён** `_SCREAMING_SNAKE` оригинала.
- Глобальные переменные-конфиг: `UpperCamel` или `UPPER_SNAKE` для констант. Локальные — `local lower`.
- Всегда `local` внутри функций. Всегда кавычки вокруг расширений: `"$var"`, `"${arr[@]}"`.
- `[[ ... ]]` вместо `[ ... ]` в bash-коде. Арифметика — `(( ... ))`.
- Временные файлы: `mktemp -d` + `trap 'rm -rf "$tmp"' EXIT`. Никаких `/tmp/fixed_name_$RANDOM`.
- Никакого `eval` и никакого `source` пользовательских данных (манифестов). Парсим вручную.
- **Никакой самомодификации скрипта** (оригинал sed-ом вшивает MD5 в себя — бан).
- Идемпотентность: повторный запуск install/extract не должен ломаться и не плодит мусор.
- Коды возврата осмысленные. Ошибка → stderr + ненулевой код. Не `exit 0` после фейла.

## 2. Комментарии

- Только `#`. На английском. По делу — объясняют **почему**, а не пересказывают код.
- **Запрещены** баннеры-украшения вида `######### ---- SETTINGS ---- #########`.
- Не оставлять закомментированный мёртвый код «на память» (у оригинала его горы).
- Один-два `#` на функцию-заголовок (что делает + неочевидные побочки) — достаточно.

Плохо (как в оригинале):
```bash
######### ---- -------- ---- #########
######### ---- SETTINGS ---- #########
function _INSTALLER_SETTINGS() { # -= (2) =-
```
Хорошо:
```bash
# Build a .bs package from a prepared source dir + manifest.
build_package() {
```

## 3. Зависимости и портабельность

- Разрешено: `bash`, `coreutils`, `tar`, `xz`/`gzip`, `find`, `grep`, `sed`, `awk`, `ldd`.
- Опционально (мягкая деградация, проверять `type -p`): `sha256sum`, `update-desktop-database`.
- **Никаких** вкомпиленных бинарей в репозитории. Ни 7-Zip, ни плейсхолдеров `ExeFile-*`.
- Никаких бинарь-блобов в гите вообще (иконки — SVG или генерим; примеры — крошечные).

## 4. Структура и DRY

- Логика арх-детекта — в **одном** месте (`core.sh`), не дублировать case по 3 раза, как оригинал.
- UI-вывод — только через `ui.sh` (единый стиль цветов/префиксов).
- Все пользовательские строки — через `i18n.sh`/локали. В коде — ключи, не литералы.
- Пути установки — единая таблица в одном модуле, не размазывать `if System/User` по всему файлу.

## 5. Тесты и проверки (Definition of Done)

- `tests/lint.sh` гоняет `shellcheck` по всем `.sh` — **0 ошибок** (warnings обоснованно глушим директивой).
- `tests/e2e.sh`: собрать `examples/hello` → запустить портативно → `--install` (user) →
  проверить ярлык/лаунчер в XDG → `--uninstall` → проверить чистоту. Зелёный прогон обязателен.
- Любой PR-агент перед сдачей: прогнать оба скрипта, приложить вывод.

## 6. Git

- Ветка под фичу, осмысленные коммиты (Conventional Commits приветствуется).
- Не коммитить артефакты сборки (`*.bs`, кэши) — добавить в `.gitignore`.
- Коммитить/пушить только по явной просьбе пользователя.

## 7. Сатира — рамки

- Язык README — русский, гиперболизированный, едкий. UI — двуязычный через локали, тоже с перчинкой.
- Правило пары: **громкое заявление + честная расшифровка**. Сатира не должна вводить в заблуждение
  технически. Пользователь, прочитав, должен точно понимать, что делает инструмент.
- Цель стёба — архаика/говнокод/ложные обещания оригинала и индустрии. Лёгкие отсылки к
  публичной риторике автора (мессианство, «дедовщина», валидация через ИИ) допустимы как приём,
  по реальным цитатам (см. SATIRE-SOURCE.md). Без личных оскорблений и частной жизни.
- MIT: копирайт оригинала и его автор — на месте в LICENSE/NOTICE, без искажений.
- Материал для пародии берём из `SATIRE-SOURCE.md` (разбор публикаций автора), не выдумываем тезисы.
- Не перебарщивать в самом коде: комментарии остаются техническими. Сатира живёт в README,
  UI-строках и docs — не в логике.

## 8. Анти-паттерны оригинала (чек-лист «так не делаем»)

Полный разбор с ссылками на legacy-строки — в `ANTIPATTERNS.md` (39 пунктов). Краткий чек-лист:

- [ ] монолит на 2000 строк → модули
- [ ] `_SCREAMING_FUNC` → `lower_snake_case`
- [ ] баннеры `####### ----` → обычные комментарии
- [ ] `read -r pause` после каждого шага → промпты только в точках реального выбора
- [ ] MD5 как «защита» → sha256 честно как контроль целостности, опционально
- [ ] sed переписывает сам скрипт → данные хранятся в данных, не в коде
- [ ] вкомпиленный 7-Zip в репо → системный xz/tar
- [ ] 8 бинарей под платформы в одном пакете → 1 пакет = 1 арх
- [ ] `/portsoft` в корне ФС → XDG / opt / usr-local
- [ ] дублирование арх-case x3 → одна функция детекта
- [ ] `source` манифеста/конфига пользователя → безопасный парсер
