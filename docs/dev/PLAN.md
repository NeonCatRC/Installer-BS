# Installer-BS — мастер-план форка

Пародийный, но **рабочий** форк `Installer-SH` (Андрей Цымбалов / Chimbal, MIT).
Документ — единый источник правды по архитектуре и решениям. Меняем его, а не память агентов.

---

## 0. Что это и зачем

`Installer-SH` подаёт себя как «решение проблемы зависимостей Linux», а по факту:
распаковывает заранее собранные бинари в `~/portsoft/<арх>/<имя>/`, делает ярлык в меню,
тащит в репозитории чужие бинари 7-Zip и плейсхолдеры `ExeFile-*`, MD5-«проверки» ради
театра и sed-ом переписывает сам себя. Один файл `installer.sh` на ~2000 строк.

`Installer-BS` берёт здравое зерно (портативный софт без рута, изоляция конфигов,
интеграция в меню) и делает это **честно, модульно и без говнокода**, а в текстах —
едко высмеивает архаику оригинала, оставаясь технически точным.

Бренд: **Installer-BS**. Три расшифровки, все верные:
- **B**ull**S**hit — честная: оригинал и есть тот самый BS, который мы вычищаем (исходная задумка названия);
- **Ba**sh **S**cript — техническая;
- **B**undled **S**oftware — приличная для релиз-ноутов.
CLI-команда: `bs`. Расширение пакета: `.bs` (исполняемый bash-самораспаковщик).

## 1. Зафиксированные решения (НЕ переоткрывать без причины)

1. **Язык** — чистый модульный Bash. Zero-deps: только coreutils + `tar`/`xz`/`gzip`.
   POSIX-дружелюбно где разумно. Никаких вкомпиленных бинарей в репо.
2. **Формат пакета** — один самораспаковывающийся файл `name-version-arch.bs`:
   `stub.sh` (раннер) + маркер + `tar.xz` payload в хвосте. Техника makeself/AppImage,
   но на системных tar/xz, без FUSE и без 7-Zip.
3. **Поведение пакета** — гибрид:
   - без аргументов → портативный запуск (распаковка в кэш, exec), как AppImage;
   - `--install [--system]` → интеграция в **стандартные** каталоги;
   - `--uninstall` → снятие;
   - `--extract`, `--info`, `--help`.
4. **Каталоги установки** — строго стандартные, **никаких папок в корне** (`/portsoft` — грех оригинала):
   - User (дефолт, без рута): `$XDG_DATA_HOME/installer-bs/<name>/`, лаунчер `~/.local/bin/<name>`,
     ярлык `~/.local/share/applications/<name>.desktop`, иконка `~/.local/share/icons/...`.
   - System (опц., рут): `/opt/<name>/`, лаунчер `/usr/local/bin/<name>`,
     ярлык `/usr/local/share/applications/` (или `/usr/share/...` если доступно).
   - Портативный кэш: `$XDG_CACHE_HOME/installer-bs/<name>-<version>/`.
5. **Мультиарх** — 1 пакет = 1 арх/ОС. Арх в имени. Нужен arm — собираешь второй файл.
   Это сознательная починка главной архаики оригинала (8 бинарей в одном пакете).
6. **Сборщик** — appimagetool-стиль: берёт готовый каталог + `manifest` → выдаёт `.bs`.
   Компиляцию из исходников НЕ делаем (это на пользователе/CI). Архитектура манифеста
   не должна мешать добавить рецепты-сборку позже, но сейчас её нет.
7. **Совместимость/зависимости** — только **бандлинг библиотек**: кладём нужные `.so`
   рядом, лаунчер подхватывает через `LD_LIBRARY_PATH`. Без sandbox (bwrap), без qemu.
   Честный посыл: «мы не «решили» зависимости — мы их аккуратно завернули».
8. **Тексты** — комментарии в коде на английском (по делу, только `#`), пользовательский
   UI через локали `ru`/`en`, README на русском. Сатира едкая, но:
   - копирайт оригинала сохраняем (требование MIT), добавляем fork-notice;
   - стёб по концепции и коду, можно частично пройтись по личности как отсылка.
9. **Платформа** — целимся в **Linux**. BSD-театр оригинала (дубль-ветка под FreeBSD в каждой
   функции) выкидываем. Но платформо-специфику изолируем в **один модуль** `lib/platform/linux.sh`,
   чтобы при реальной нужде доложить `freebsd.sh` без размазывания веток по коду. Поле `os` в
   манифесте остаётся. Инструмент POSIX-дружелюбен (на BSD с bash может завестись), но это не
   обещаем и спец-код не тащим.

## 2. Новая иерархия файлов

Оригинал: двойная вложенность `Installer-SH/Installer-SH/...`, `installer-data/{program_files,
system_files,tools}`, вкомпиленные 7-Zip и `ExeFile-*`, `.ods`/`.kra`/`.jpg` в гите, монолит.

Целевая структура форка (всё осмысленно, бинарей в гите нет):

```
Installer-BS/
├── README.md                 # RU, гиперболизированный, едкий
├── LICENSE                   # MIT: копирайт оригинала + fork-notice
├── NOTICE                    # происхождение форка, что изменено
├── bs                        # единая точка входа CLI (тонкий диспетчер)
├── lib/                      # модульная bash-библиотека (source из bs)
│   ├── core.sh               #   globals, разбор аргументов, dispatch
│   ├── ui.sh                 #   цвета, prompt'ы, вывод (без read-pause-спама)
│   ├── i18n.sh               #   загрузка локали по $LANG
│   ├── manifest.sh           #   безопасный парсер манифеста (без eval/source)
│   ├── pack.sh               #   `bs build`: каталог+манифест -> .bs
│   ├── bundle.sh             #   сбор .so через ldd, exclude-list
│   └── platform/
│       └── linux.sh          #   платформо-специфика (sed/stat/пути); BSD — отдельным модулем потом
├── locales/
│   ├── en.sh
│   └── ru.sh
├── template/
│   ├── stub.sh               # раннер, который префиксится к payload пакета
│   └── manifest.example      # эталонный манифест с комментариями
├── examples/
│   └── hello/                # минимальный рабочий пример (build->run->install)
│       ├── manifest
│       └── bin/hello
├── docs/
│   ├── PACKAGE-FORMAT.md      # спецификация формата .bs и манифеста
│   ├── ARCHITECTURE.md        # как устроен раннтайм и сборщик
│   ├── PORTING-FROM-SH.md     # таблица «грех оригинала -> как у нас»
│   ├── MUSEUM.md              # «Музей ошибок прошлого автора» (RU, публичный, сатира)
│   └── dev/                   # планы для агентов (этот каталог)
│       ├── PLAN.md
│       ├── GUIDELINES.md
│       ├── PACKAGE-FORMAT.md  # черновик спеки (переезжает в docs/ при готовности)
│       └── AGENT-TASKS.md
└── tests/
    ├── lint.sh               # shellcheck по всем .sh
    └── e2e.sh                # сборка примера и прогон жизненного цикла
```

Что **выпиливаем** из оригинала:
- `installer-data/tools/7zip/*` — чужие бинари. Используем системные `tar`/`xz`.
- `installer-data/.../ExeFile-*` — плейсхолдер-бинари под 8 платформ.
- `Menu-Categories.ods`, `icons.kra`, `Preview.jpg`, `field-testing-*.png` — бинарь-мусор в гите.
- двойную вложенность `Installer-SH/Installer-SH`.
- `for-tests-in-VM-*.sh` — заменяем на `tests/e2e.sh` (чисто, без mount tmpfs ради «места на Live-CD»).
- `base_data.tar.xz` + создание `/portsoft` и кастомной категории меню — не нужно, ставим в XDG.
- MD5-театр, sed-самомодификацию скрипта, `_SCREAMING_FUNC` нейминг, баннеры `####### ----`.

## 3. Раннтайм пакета (template/stub.sh)

Самораспаковщик `.bs` при запуске:

1. Находит смещение payload в собственном файле по маркеру
   (`tail -n +N "$0" | tar -xJ -C "$dest"`), извлекает в кэш идемпотентно
   (повторный запуск не распаковывает, если версия уже извлечена).
2. Встроенный манифест читается из шапки (безопасно, парсером, не `source`).
3. Режимы:
   - **run** (дефолт): выставляет `LD_LIBRARY_PATH` на бандл-либы (если есть), изолирует
     конфиги через `XDG_*`/`HOME` опционально, `exec` основного бинаря с `"$@"`.
   - **--install [--system]**: копирует payload в XDG/opt, ставит лаунчер и `.desktop`,
     пишет **список установленных файлов** в data-каталог (для чистого удаления —
     никакого sed-инъекта в скрипт деинсталлятора, как в оригинале).
   - **--uninstall**: читает тот список, удаляет, обновляет `update-desktop-database` если есть.
   - **--extract DIR**, **--info**, **--help**.
4. Ошибки — внятные, с кодом возврата и одной сатирической строкой, без `read pause` на каждом шаге.

Изоляция конфигов (наследие PortSoft-режима, но честно): по флагу манифеста перенаправляем
`XDG_CONFIG_HOME/XDG_DATA_HOME/...` в data-каталог приложения. Это и есть весь «PortSoft» —
честно называем вещи своими именами.

## 4. Сборщик (lib/pack.sh — `bs build`)

`bs build <src-dir> [-o out.bs]`:

1. Валидирует `<src-dir>/manifest` (обязательные поля: `name`, `version`, `arch`, `exec`).
2. Если `bundle_libs = true`: `ldd` основного бинаря, копирует не-системные `.so` в `payload/lib`,
   по exclude-list (glibc/ld-linux НЕ бандлим — как AppImage). Предупреждает о найденном.
3. Пакует payload в `tar.xz` (системный `xz -9`, фоллбэк `gzip`).
4. Склеивает `template/stub.sh` + маркер + payload → `name-version-arch.bs`, `chmod +x`.
5. Считает **sha256** (опционально, через `sha256sum`) и кладёт рядом `.sha256` —
   честно: «это от битой копии, а не «крипто-защита», как MD5 у оригинала».

Манифест — декларативный `key = value`, парсится построчно (см. PACKAGE-FORMAT.md),
НЕ исполняется как bash. Это убирает класс багов и дыр оригинала.

## 5. Сатира и тон (рамки)

- README RU: сохраняем энергию вступления оригинала («две большие папочки…»), но острее
  и про суть — каждое гиперболизированное заявление в паре с честным «что на самом деле».
- UI-строки: информативно + ехидно. Пример (`--install`): «Кладу файлы в XDG-каталоги, как
  взрослые. Папок в корне твоей ФС не будет — мы не дикари 2009-го».
- Сквозной гэг: оригинал «РАЗЛОМАЛ проблему зависимостей» → наш честный контр-тезис:
  «Мы её НЕ решили. Её нельзя решить. Мы завернули `.so` рядом — это бандлинг, и да, это всё,
  что делает половина твоих любимых форматов».
- LICENSE/NOTICE — уважительно: имя автора и копирайт на месте, стёб только по коду/подходу.

## 6. Порядок работ (вехи)

- **M0 — Скелет**: чистка репо от бинарь-мусора, новая структура, LICENSE+NOTICE, `.gitignore`.
- **M1 — Ядро CLI**: `bs`, `core/ui/i18n`, локали `en/ru`. `bs --help` работает.
- **M2 — Формат + раннтайм**: `template/stub.sh`, `manifest.sh`, спека PACKAGE-FORMAT.md.
- **M3 — Сборщик**: `pack.sh` (`bs build`) + `bundle.sh`.
- **M4 — Пример + e2e**: `examples/hello`, `tests/e2e.sh` (build→run→install→uninstall).
- **M5 — Тексты**: README RU, docs/ (ARCHITECTURE, PORTING-FROM-SH).
- **M6 — Качество**: `tests/lint.sh` (shellcheck-clean), bats-тесты, CI.
