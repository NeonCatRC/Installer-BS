# GUI launcher — план модернизации TUI (Фаза 0)

Хэндофф для следующей сессии. Самодостаточно: решение, цель, мок, движок, задачи, тесты.

## Решение (зафиксировано)

Модернизируем **текущий bash-TUI** лаунчера до уровня «самопального `dialog`». **Без Go.**

- **Go-TUI — отклонён:** красивее, но ELF → per-arch сборки + Go-тулчейн в пайплайне + бинарь ~3–8 МБ.
  Теряем `arch=any` и бьём по слогану «ноль зависимостей, 1 файл на всё».
- **Fat multi-arch в одном `.bs` — отклонён:** это ровно [Музей, Зал 5](../MUSEUM.md) (оригинал пихал 8 бинарей
  в пакет, мы это высмеиваем). Если когда-нибудь — только явный `bs build --fat` с честной табличкой.
- **Выбрано:** zero-dep bash-TUI, остаётся `arch=any`, один универсальный `.bs`, ноль внешних зависимостей.
  zenity-бэкенд (оконный GUI при наличии дисплея) **не трогаем** — он уже работает.

Цель — «лучшее оформление» в характере проекта. Жертвы приняты осознанно (ниже).

## Файл

Правим только `examples/bs-gui/app/installer-bs-gui` (он в lint-наборе `tests/lint.sh`).
Внутри уже есть абстракция `ui_menu / ui_confirm / ui_run_log / ui_pick_file / ui_message` с двумя
ветками (zenity / tui). Меняем **только tui-ветку** (новый движок); zenity-ветку оставляем как есть.
Весь интерактив TUI уже идёт через `/dev/tty` — сохранить.

Установленные (скролл + счётчик + полоса справа):

тем же стилем (см. историю чата / повторить по аналогии).

## Жертвы (приняты)

- **Мышь** — нет (в bash дорого/хрупко).
- Самый слик-рендер/готовые виджеты (таблицы, поля-с-правкой) — нет; делаем минимум руками.
- Пуленепробиваемость на «дичь»-терминалах — нет; при отсутствии capable-tty/`tput` **деградируем в
  текущее нумерованное меню** (фолбэк обязателен).

## Что держим

`arch=any`, один файл ~40–60 КБ, ноль зависимостей, bash 4.3 (Ubuntu 16.04), shellcheck-clean.

## Движок (что написать)

1. **Терминал-режим:** `stty` raw (`-icanon -echo`), скрыть курсор; **EXIT/INT/TERM-trap** обязательно
   восстанавливает (`stty sane`, показать курсор, опц. выйти из alt-screen). Без этого Ctrl-C ломает терминал.
2. **Опц. alt-screen** (`tput smcup`/`rmcup`) — чтобы не сорить в скроллбэк (решить да/нет; по умолчанию да).
3. **Ридер клавиш:** `read -rsn1` → если `ESC`, дочитать с **таймаутом** (`read -t 0.05`) для разбора
   `ESC [ A/B/C/D` (стрелки) vs одиночный ESC. Токены: UP/DOWN/LEFT/RIGHT/ENTER/ESC/HOME/END/CHAR(x)/q.
4. **wcwidth-паддинг:** функция «дисплей-ширина строки» (ASCII=1; кириллица/основной CJK=широкие диапазоны)
   + pad/truncate до N колонок. Нужна для ровного правого края рамки с кириллицей.
5. **Рисование:** хелперы `frame_top/mid/bot`, строка-заголовок, строка статус-бара, строка списка с
   подсветкой (инверсия `\e[7m`), скролл-вьюпорт (offset+window), глифы полосы `▲ ┃ ▼`, счётчик `i/N`.
6. **Перерисовка без мигания:** позиционирование `tput cup` (или ANSI `\e[row;colH`), переписываем только
   изменившиеся строки (или весь кадр поверх, но без `clear`). 
7. **Ресайз:** ловить **SIGWINCH** → пересчитать `tput cols/lines`, перерисовать.
8. **Тема/цвет:** уважать `NO_COLOR` и не-tty; палитра как сейчас (зелёные акценты, dim статус).

## Примитивы на движке (переписать tui-ветки)

- `ui_menu` — список со стрелками+подсветкой+скроллом; возврат выбранной метки на stdout. Цифры-хоткеи опц.
- `ui_confirm` — две кнопки `[Да] [Нет]`, навигация ←→, дефолт = Нет; exit-status.
- `ui_run_log` — шапка + живой вывод команды + `[exit N]` + пауза «Enter».
- `ui_message` — обёрнутый текст (`fold -s`) + пауза.
- `ui_pick_file` — поле ввода пути (вернуть в canonical-режим на время `read -e`, потом снова raw).
- (опц.) фильтр `/` в списках.

## Разбивка задач (инкремент, тест после каждого шага)

1. Движок-ядро: raw-режим + trap-восстановление + ридер клавиш + wcwidth-pad + draw-хелперы (frame/header/status).
2. `ui_menu` со стрелками+подсветкой (без скролла) — прогон через pty.
3. Скролл-вьюпорт + полоса + счётчик для длинных списков.
4. `ui_confirm` (←→ кнопки), `ui_run_log`, `ui_message`, `ui_pick_file` (raw↔canonical для `read -e`).
5. SIGWINCH-ресайз; тема/NO_COLOR; **фолбэк** в нумерованное меню, если нет capable-tty/`tput`.
6. (опц.) фильтр `/`.
7. Финал: матрица pty-тестов + shellcheck + `tests/lint.sh` + `tests/e2e.sh` (62/0) + e2e install/uninstall
   лаунчера; пересобрать хэндофф `.bs`; обновить `examples/bs-gui/README.md` (тест-заметки) и, при желании,
   эпилог Зала 6.

## Тестирование (харнес уже отработан)

- Драйв через псевдотерминал: `printf '<seq>' | python3 -c "import pty;pty.spawn(['bash','/tmp/gui.bs'])"`.
  Последовательности: стрелки `\x1b[A`/`\x1b[B`/`\x1b[C`/`\x1b[D`, Enter `\r`, ESC `\x1b`, `q`.
- Проверять: навигация/выбор, скролл на длинном списке, confirm Да/Нет, лог-пауза, **восстановление
  терминала после выхода** (stty sane), фолбэк без tput.
- Стрипать ANSI для grep: `sed 's/\x1b\[[0-9;?]*[A-Za-z]//g'`.

## Риски / открытые вопросы

- Тайминг ESC-disambiguation (ESC vs стрелка) — подобрать `-t` (0.03–0.1).
- Восстановление терминала при сигналах — trap на EXIT INT TERM HUP.
- Покрытие wcwidth-таблицы (эмодзи/комбинируемые — игнор, не критично).
- alt-screen: включать ли (да/нет).
- Дефолт кнопки confirm = Нет (безопасно).
- Готовый релиз: после Фазы 0 — обновить `bs-gui-0.3.0` (или выпустить `0.3.1`).
