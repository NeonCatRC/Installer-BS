# Каталог анти-паттернов оригинала → как делает Installer-BS

Полный разбор грехов `Installer-SH` (исходники в `docs/legacy/`). Это одновременно:
инженерный чек-лист «так НЕ делаем» и боеприпас для README/PORTING-FROM-SH.
Принцип проекта: чем чище наш выходной код, тем больнее сатира — мы показываем «как надо» делом.

Ссылки на строки — по `docs/legacy/installer.sh` (бывший монолит) и соседним файлам.

---

## A. Структура и модульность

1. **Монолит ~2000 строк в одном файле** (`installer.sh`). Вся логика, настройки, строки,
   локализация-фоллбэк, паковка, чистка — в кучу.
   → BS: `bs` + `lib/*.sh`, один модуль = одна ответственность.
2. **Ручная нумерация этапов** в комментариях: `# -= (13.1) =-`, `_MAIN` зовёт функции по
   номерам (строки 10-21). Порядок держится на дисциплине, не на структуре.
   → BS: явный pipeline из именованных функций, зависимости через аргументы/возвраты.
3. **Дублирование арх-детекта 3×**: `case` в `_INSTALLER_SETTINGS` (152-164), повтор в `launcher`
   (31-43), плюс проверки в `_CHECK_SYSTEM`.
   → BS: одна функция `core::detect_platform`, результат переиспользуется.

## B. Нейминг и комментарии

4. **`_SCREAMING_SNAKE` с ведущим подчёркиванием** для всех функций: `_INSTALLER_SETTINGS`,
   `_IMPORTANT_CHECK_FIRST`. Шумно, не идиоматично.
   → BS: `lower_snake_case` / `module::func`.
5. **Баннеры-украшения**: `######### ---- SETTINGS ---- #########`, десятки пустых
   `######### -------------- #########` (строки 785-794 и др.).
   → BS: обычные `#`-комментарии по делу.
6. **Капсовые «КОСТЫЛЬ ДЛЯ КРИВЫХ ДИСТРИБУТИВОВ…»** повторяются дословно 4+ раза
   (663, 1663, 1687, 1729). Копипаст вместо функции.
   → BS: если костыль реально нужен — одна функция с одним комментарием-почему.
7. **`DON'T TOUCH THIS!` / `DO NOT TOUCH WITHOUT A SERIOUS REASON`** (4, 134-136, 51) —
   код, написанный из страха, а не из понимания.
   → BS: если место хрупкое — рефакторить, а не пугать.
8. **Мёртвый закомментированный код** «на память»: `#_SET_LOCALE`, `# _INSTALLER_SETTINGS`,
   закомментированные `_POST_INSTALL_UPDATE_MENU_*` ветки (217-219), `#export SOME_IMPORTANT_VARIABLE`.
   → BS: мёртвый код удаляем, история — в git.

## C. Безопасность исполнения (bash-корректность)

9. **Нет `set -euo pipefail` нигде.** Ошибки молча проглатываются, выполнение едет дальше.
   → BS: строгий режим во всех исполняемых скриптах.
10. **Парсинг вывода `ls` в массивы** через `while read < <(ls "$dir")` (1412-1415) с глобальным
    `IFS=''`. Ломается на именах с переводами строк/спецсимволами.
    → BS: globbing/`find -print0` + `read -d ''`.
11. **Busy-loop «делай пока не получится»**: `while [ "$All_Renamed" == "false" ]; do find|sed|xargs mv … done`
    (1404-1408) — переименование в цикле до удачи, без предела попыток.
    → BS: детерминированная операция один раз, ошибка → стоп с диагностикой.
12. **`grep -rl … | xargs sed -i`** для подстановки плейсхолдеров по всему temp (891-899, 1390-1400).
    Без `-print0`, ломается на пробелах/спецсимволах в путях.
    → BS: подстановка по явному списку файлов, безопасное экранирование.
13. **Sentinel-строки как значения по умолчанию**: `CurrentArchitectureNormalized="x32 or x64"` (6).
    «Значение», которое не значение.
    → BS: пустая строка/`unset` + явная проверка, либо `return` с кодом.

## D. Безопасность

14. **`source` пользовательских/внешних файлов** = выполнение произвольного кода:
    локаль `source "$Locale_File"` после слабой проверки по `grep` версии (1929-1933),
    `source "$HOME/.config/user-dirs.dirs"` (288), `source ish-settings` в launcher (53).
    → BS: данные парсятся как данные (`manifest::parse`), никакого `source` чужого ввода.
15. **`chmod 777` на temp-каталог** `/tmp/installer-sh` (1007). World-writable, гонки/симлинк-атаки.
    → BS: `mktemp -d` (0700) + `trap` на очистку.
16. **Предсказуемые имена в `/tmp`**: `/tmp/installer-sh/<name>_$RANDOM_$RANDOM` (700-701).
    `$RANDOM` — не криптослучаен.
    → BS: `mktemp -d`.

## E. Данные-в-коде и самомодификация

17. **Скрипт sed-ом переписывает САМ СЕБЯ**: вшивает MD5 архивов обратно в `installer.sh`
    (377-386). Код мутирует собственный исходник.
    → BS: метаданные живут в манифесте/рядом с пакетом, не в теле программы.
18. **Деинсталлятор собирается sed-инъекцией списка файлов** в шаблон: `sed -i "s~FilesToDelete=(~&\n$CurrentFile~"`
    (1660, 1684), да ещё с ре-`chmod` после КАЖДОЙ итерации «на случай слёта прав».
    → BS: список установленных файлов пишется в data-файл `.bs-files`, удаление читает его.

## F. Портабельность / FHS / XDG

19. **Папка `/portsoft` в КОРНЕ ФС** (system) + `~/portsoft` (139-140, спека PortSoft) —
    самопальная иерархия вместо FHS/XDG.
    → BS: `/opt`, `/usr/local`, `$XDG_*`. Никаких каталогов в корне.
20. **Своя таксономия «ARCHI_FOLDER»** (`/portsoft/x86_64`, `/script`, `/other`) — переизобретение
    того, что уже решено стандартами.
    → BS: не плодим таксономий, 1 пакет = 1 арх в имени.
21. **Абсолютный `PATH_TO_FOLDER` запекается в каждый файл** через sed (bin-шаблон, .desktop:
    `Exec=PATH_TO_FOLDER/launcher`). Перенёс каталог — всё сломалось.
    → BS: относительные пути от каталога пакета, разрешаются в рантайме.
22. **Кастомный XML `.menu`** с ручной вложенностью `<Menu>` и инъекцией категории
    (`menu/applications-merged/...menu`) — переизобретение XDG-меню, требует своей категории.
    → BS: стандартный `.desktop` в `applications/`, категории XDG как есть.
23. **Имя приложения как XDG-категория**: `Categories=UNIQUE_APP_FOLDER_NAME;…` (.desktop:24).
    Засоряет глобальное пространство категорий уникальным id.
    → BS: валидные XDG-категории (`Utility;` и т.п.), id приложения — в имени файла.

## G. Враждебный UX

24. **Принудительный ресайз терминала пользователя**: `printf '\033[8;32;100t'` (749),
    `printf '\033[8;30;100t'` в деинсталляторе (21). Лезет в чужое окно.
    → BS: не трогаем геометрию терминала.
25. **`clear; clear` «костыль для старого GNOME»** (976) — двойная очистка экрана.
    → BS: не чистим экран без нужды; вывод дружелюбен к логам/пайпам.
26. **`read -r pause` после каждого шага** (везде в debug + подтверждения) — нельзя
    проскриптовать, постоянные «нажмите Enter».
    → BS: промпты только в точках реального выбора, флаг `--yes`, не-интерактивный режим.
27. **`Terminal=true` в .desktop по умолчанию** (.desktop:21) — GUI-приложение открывается
    с лишним окном терминала, потому что launcher делает `read pause`.
    → BS: `Terminal=false` по умолчанию, терминал только если приложение реально консольное.
28. **`_ABORT` всегда интерактивен**: `read -r pause; clear; exit 1` (1060) — даже в скриптах.
    → BS: ошибка → stderr + код возврата; интерактив только в TTY.

## H. Гигиена репозитория

29. **Чужие бинари в гите**: 7-Zip `7zzs`, `7zz-bsd`, `7zzs-x86` + их `History.txt`/`License.txt`.
    → BS: системный `xz`/`tar`, ноль бинарь-блобов.
30. **8 плейсхолдер-бинарей** `ExeFile-{lin,bsd,armlin,armbsd}{32,64}` в гите.
    → BS: примеры собираются в e2e, бинари не коммитятся.
31. **Бинарь-мусор**: `Menu-Categories.ods`, `icons.kra`, `Preview.jpg`, `field-testing-*.png`,
    `base_data.tar.xz`, `MD5-Hash.txt` (растёт через `>>`).
    → BS: ассеты — текст/SVG или генерятся; артефакты в `.gitignore`.
32. **Текст MIT-лицензии скопирован в подвал КАЖДОГО скрипта** (~80 строк × N файлов).
    → BS: один `LICENSE` + краткий SPDX-заголовок где нужно.
33. **Дублирующиеся файлы**: `desktop/UNIQUE_APP_FOLDER_NAME.desktop` и
    `menu/apps/.../UNIQUE_APP_FOLDER_NAME.desktop` — идентичны.
    → BS: один шаблон, генерация из манифеста.
34. **Двойная вложенность** `Installer-BS/Installer-SH/installer-data/...`.
    → BS: плоско и осмысленно.

## I. Мёртвые/выдуманные механизмы

35. **Несуществующие env-переменные**: `LD_32_LIBRARY_PATH`, `LD_64_LIBRARY_PATH` (launcher 96-97,108).
    В Linux таких нет — код ничего не делает, создаёт иллюзию мультиарх-магии.
    → BS: только реальный `LD_LIBRARY_PATH`, без карго-культа.
36. **Опечатка в идентификаторе разъехалась по всему коду**: `ISHPogramArch` (Pogram вместо Program)
    — launcher 56, installer 1722/1725, ish-settings.
    → BS: ревью + shellcheck ловят такое; имена осмысленные.
37. **Сборка команды строкой + запуск через терминал**: `StringMessage="bash -c '…'"` затем
    `$terminal_executable -e "$StringMessage"` (launcher 123-137). Ад экранирования.
    → BS: массивы аргументов, без строковой сборки команд.

## J. Театр целостности

38. **MD5 как «защита целостности»** (29-30, весь `_CHECK_MD5`). MD5 крипто-сломан; и даже как
    контроль — подаётся с пафосом «несколько независимых проверок».
    → BS: опц. `sha256` рядом с пакетом, честно подписан как «контроль битой докачки, не крипто».
39. **Слабая привязка версии локали** через точное строковое сравнение строки grep:
    `[ "$(grep Locale_Version "$f")" == "Locale_Version=\"$LocaleVersion\"" ]` (1930).
    → BS: версия — поле в данных, сравнение значений, не строк файла.

## K. Мнимая мультиплатформенность

40. **Дубль-ветка под FreeBSD в каждой функции**: `sed -i ""` vs `sed -i`, `stat -f` vs `stat -c`,
    отдельный бинарь `7zz-bsd`, ветки `if FreeBSD` по всему коду. Удваивает сложность и поверхность
    багов. При этом автор в статье сам назвал FreeBSD «ещё более мёртвой ОС, чем Linux».
    → BS: целимся в Linux; платформо-специфика — один модуль `lib/platform/linux.sh`, BSD доложить
    отдельным модулем при реальной нужде. Никаких дубль-веток в теле функций.

## L. Углублённый разбор: вектор атаки через локаль (к пп. 14, 39)

Пункты 14 (`source` чужих файлов) и 39 (слабый grep-гейт версии) сходятся в одной функции —
`_SET_LOCALE` — и складываются в разбираемый вектор атаки. Фиксируем как анти-практику (почему наш
форк парсит локаль как **данные**), всё проверено эмпирически на коде HEAD оригинала.

**A. In-package locale-файл = RCE (живой).** `source "$Locale_File"` исполняет `locales/<lang>`
как bash. Перед этим — `grep -qF 'Locale_Version="2.5"'`, проверка наличия строки → подделывается
одной строкой. В System-режиме инсталлятор эскалируется `sudo`, значит payload исполняется **root'ом**.
Иллюстрация (безобидная): locale-файл с первой строкой `Locale_Version="2.5"` и `id > /tmp/pwned`.

**B. Path traversal через `$LANG` — закрыт случайно.** `Language="${LANG%%.*}"`. Жадный `%%`
срезает от ПЕРВОЙ точки; в любом `..` точка есть → traversal схлопывается (проверено в bash):

| `LANG` | `${LANG%%.*}` (оригинал) | `${LANG%.*}` (если б одиночный `%`) |
|---|---|---|
| `../../../../tmp/evil.sh` | `` (пусто) | `../../../../tmp/evil` → `source` = RCE |
| `/tmp/evil` | `/tmp/evil` → `locales//tmp/evil` (внутри дерева) | то же |

Защита держится на **втором `%`**. Один символ при будущем «рефакторинге» — и открыт traversal-RCE
через переменную окружения.

**C. Локаль протекает в root через sudo.** Дефолтный `env_keep` в sudoers тащит `LANG`/`LANGUAGE`/`LC_*`
в команду под root; опасные `LOCPATH`/`NLSPATH`/`GCONV_PATH` штатный `env_reset` вырезает (классика
«подсунь скомпилированную локаль/iconv-модуль → код в чужом процессе» закрыта, **если** sudoers не
ослаблен). Вывод: вся locale-зависимая логика крутится под root — лёд тонкий.

**D. DoS / логика (low).** Форс `C`/несуществующей локали роняет UTF-8 в утилитах, что парсят вывод;
десятичный разделитель (запятая vs точка) может перевести парс размеров. Баг-фабрика, не эксплойт.

→ BS: локаль — данные (`i18n::t` по ключу), не `source`; путь к файлу из `$LANG` не строим; подлинность —
`sha256`/OpenPGP, а не «магическая строка» внутри файла; code-path не управляется env злоумышленника.
Экспонат — Музей, Зал 22.
