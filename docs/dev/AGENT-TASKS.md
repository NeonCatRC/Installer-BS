# Задачи для агентов (work packages)

Готовые к передаче брифы. Каждый агент ОБЯЗАН сначала прочитать `PLAN.md` и `GUIDELINES.md`.
Запрет: переносить плохие практики оригинала (см. чек-лист в GUIDELINES §8).

Условные обозначения: **Вход** — что уже есть. **Выход** — что сдать. **DoD** — критерии приёмки.

---

## Граф зависимостей и параллельность

```
WP0 (скелет) ──► WP1 (ядро CLI) ──┬──► WP2 (формат+раннтайм) ──┐
                                  ├──► WP3 (сборщик) ──────────┼──► WP4 (пример+e2e) ──► WP6 (качество)
                                  └──► (WP3 зовёт bundle.sh)    │
WP5 (тексты/докажем) — параллельно после WP2/WP3 (нужна спека) ┘
```

- Строго первым: **WP0**. Затем **WP1** (фундамент).
- После WP1 параллелятся **WP2** и **WP3**. **WP4** требует обоих. **WP5** требует спеку (WP2).
- **WP6** — финальный (нужен рабочий e2e).

## WP0 — Скелет репозитория и чистка

**Цель:** убрать бинарь-мусор оригинала, развернуть новую структуру, юридическую базу.

**Вход:** текущий репо (оригинал `Installer-SH/...`), `docs/dev/*`.

**Выход:**
- Новая структура каталогов из `PLAN.md §2` (пустые модули-заглушки с шапкой-комментарием TODO).
- Удалены: `Installer-SH/installer-data/tools/7zip/*`, все `ExeFile-*`, `*.ods`, `*.kra`, `*.jpg`,
  `field-testing-*.png`, `base_data*`, `for-tests-in-VM-*.sh`, двойная вложенность.
  (Старый `installer.sh` оставить временно в `docs/legacy/` для справки ИЛИ удалить —
  согласовать с пользователем; по умолчанию переместить в `docs/legacy/installer-sh-reference.sh`.)
- `LICENSE` — MIT с сохранённым копирайтом «Андрей Цымбалов (Chimbal), 2024-2026» + строка форка.
- `NOTICE` — происхождение: форк `Installer-SH`, что изменено концептуально.
- `.gitignore` — `*.bs`, `*.sha256`, кэши, temp.
- `.gitattributes` — **принудительный LF** для `*.sh`, `bs`, `stub.sh`, `template/*`
  (разработка на Windows, цель — Linux; CRLF ломает shebang и исполнение bash). Маркеры

**DoD:** `git status` чистый по мусору; `tree` совпадает с PLAN §2; LICENSE содержит оба копирайта.
**Осторожно:** удаление бинарей через `git rm`. Не удалять `docs/dev/*`. Не трогать `.git`.

## WP1 — Ядро CLI (`bs`, core/ui/i18n, локали)

**Цель:** рабочий каркас команды `bs` с диспетчером, выводом и локализацией.

**Выход:**
- `bs` — точка входа: `set -euo pipefail`, определяет свой каталог, `source lib/*.sh`, зовёт `core::dispatch "$@"`.
- `lib/platform/linux.sh`: платформо-специфика (варианты `sed -i`, `stat`, базовые пути) за
  тонким интерфейсом. **Никаких** `if FreeBSD` веток в теле других функций; BSD — отдельный
  модуль в будущем. Linux — единственная цель сейчас.
- `lib/core.sh`:
  - **единая** функция детекта ОС/арх (`uname -s/-m` → нормализованные `os`/`arch`) — один источник;
  - разбор глобальных флагов (`--help`, `--version`, `--lang`, `--yes/-y`, `--debug`);
  - dispatch подкоманд: `build`, `help`, `version` (заготовки под остальное).
- `lib/ui.sh`: цвета (с авто-отключением если не TTY/`NO_COLOR`), `ui::info/warn/error/ok`,
  `ui::ask` (промпт только при реальном выборе, уважает `--yes`). Без `read pause`-спама.
- `lib/i18n.sh`: грузит `locales/<lang>.sh` по `$LANG`, фоллбэк `en`. Ключи `STR_*`.
- `locales/en.sh`, `locales/ru.sh`: набор стартовых строк (help, ошибки, общие).

**DoD:** `./bs --help` и `./bs version` работают на чистом bash; `LANG=ru_RU.UTF-8 ./bs --help`
даёт русский; shellcheck-clean; цвет гаснет при `NO_COLOR=1` и в пайпе.

## WP2 — Формат пакета и раннтайм (`template/stub.sh`, `manifest.sh`, спека)

**Цель:** самораспаковывающийся раннтайм и безопасный парсер манифеста.

**Вход:** `docs/dev/PACKAGE-FORMAT.md`.

**Выход:**
- `lib/manifest.sh`: `manifest::parse <file>` → ассоциативный массив; безопасно (без eval/source);
  валидация обязательных полей; тест на инъекцию (значение со `;`/`$()` не исполняется).
- `template/stub.sh`: раннтайм пакета:
  - поиск payload по маркеру `__BS_PAYLOAD__`, извлечение в кэш идемпотентно (`tail|xz -dc|tar`);
  - чтение встроенного манифеста из шапки;
  - режимы: run (дефолт), `--install [--system]`, `--uninstall`, `--extract DIR`, `--info`, `--help`;
  - установка строго в XDG/opt/usr-local (PLAN §4), список файлов в `.bs-files`;
  - `LD_LIBRARY_PATH` на бандл-либы; опц. `isolate_home` через `XDG_*`;
  - внятные ошибки + 1 сатирическая строка; чужая арх → понятный фейл.
- `docs/PACKAGE-FORMAT.md`: финализированная спека (из черновика).

**DoD:** ручной тест: вручную собранный `stub.sh + tar.xz` запускается, `--info` печатает манифест,
`--extract` распаковывает, инъекционный манифест безопасен. shellcheck-clean.

## WP3 — Сборщик (`lib/pack.sh` = `bs build`, `lib/bundle.sh`)

**Цель:** превращение каталога+манифеста в `.bs`.

**Вход:** `manifest.sh` (WP2), `template/stub.sh` (WP2).

**Выход:**
- `lib/pack.sh`: `bs build <src> [-o out.bs]`:
  валидация манифеста; (опц.) `bundle::collect`; `tar -cJf` payload; склейка `stub + маркер + payload`;
  `chmod +x`; опц. `sha256sum` → `.sha256`. Дублирование манифеста в шапку пакета.
- `lib/bundle.sh`: `bundle::collect <exec> <dest-lib-dir>`:
  `ldd` → список `.so` → копировать кроме exclude-list (`ld-linux*`,`libc`,`libm`,`libpthread`,
  `libdl`,`librt`; `libstdc++` опц.). Печатать что взято/что пропущено.

**DoD:** `bs build examples/hello` (после WP4 даст пример) выдаёт рабочий `.bs`; повторная сборка
идемпотентна; временные файлы убираются по trap. shellcheck-clean.

## WP4 — Пример пакета и e2e-тест

**Цель:** доказать жизненный цикл целиком.

**Вход:** WP1–WP3.

**Выход:**
- `examples/hello/`: `manifest` + крошечный `bin/hello` (bash или сишный исходник, компилируемый
  в e2e; без вкомпиленного бинаря в гите) + опц. `share/hello.svg` (генерится/минимальный SVG-текст).
- `tests/e2e.sh`: `bs build examples/hello` → `./hello-*.bs` (run, проверить вывод) →
  `--install` (user, во временный `XDG_*`-префикс) → проверить лаунчер+`.desktop` → `--uninstall` →
  проверить, что всё снято. Всё во временных каталогах, без мусора в системе.

**DoD:** `tests/e2e.sh` зелёный на Linux; не оставляет файлов вне temp; не требует рута.

## WP5 — Тексты: README (RU) и docs

**Цель:** сатирический, но точный фронт проекта.

**Вход:** PLAN, GUIDELINES §7, `SATIRE-SOURCE.md` (разбор риторики автора — основа пародии), спека.

**Выход:**
- `README.md` (RU): гиперболизированный, едкий; правило пары «громкое заявление + честная расшифровка»;
  секции: что это, чем лучше `Installer-SH`, как собрать пакет, как запустить/установить, ограничения.
- `docs/ARCHITECTURE.md`: как устроены раннтайм и сборщик (для контрибьюторов).
- `docs/PORTING-FROM-SH.md`: таблица «грех оригинала → как у нас» (8 бинарей, `/portsoft`, MD5,
  sed-самомодификация, 7-Zip в репо, монолит — и наш ответ на каждое).
- `docs/MUSEUM.md`: «Музей ошибок прошлого автора» — публичный, сатирический (черновик уже есть,
  отполировать тон, сверить факты/строки legacy, докрутить связки с README).

**DoD:** тексты не врут технически; копирайт/автор оригинала корректны; стёб по коду, не по личности;
проверка пользователем тона.

## Общие правила сдачи для всех WP

1. Прочитать PLAN.md + GUIDELINES.md.
2. Ветка под WP, Conventional Commits.
3. Перед сдачей: `tests/lint.sh` (когда существует) — зелёный; приложить вывод.
4. Не коммитить `.bs`/артефакты/бинари.
5. Не пушить без явной просьбы пользователя.
6. Если решение расходится с PLAN — сначала обновить PLAN.md (раздел «решения») и согласовать.
