# Архитектура Installer-BS

Для контрибьюторов. Правила кода и стиля — в [`docs/dev/GUIDELINES.md`](dev/GUIDELINES.md).
Формат пакета — в [`docs/PACKAGE-FORMAT.md`](PACKAGE-FORMAT.md).

## Карта

```
bs                      точка входа: резолвит свой каталог, source модулей, core::dispatch "$@"
lib/
  core.sh               детект платформы (единственный), разбор глобальных флагов, диспетчер команд
  ui.sh                 вывод (цвет авто-гаснет вне TTY/NO_COLOR), info/ok/warn/error, confirm
  i18n.sh               загрузка локали по $LANG, английский — фолбэк-база; i18n::t по ключу
  manifest.sh           парсер манифеста как ДАННЫХ (без eval/source) + валидация — для сборщика
  pack.sh               `bs build`: каталог + манифест -> .bs
  bundle.sh             сбор .so через ldd (ELF, нативный хост), exclude базового libc/loader
  platform/linux.sh     платформо-специфика за тонким интерфейсом (BSD доложить отдельным модулем)
locales/{en,ru}.sh      таблицы строк (ассоциативные массивы)
template/stub.sh        раннтайм пакета: префиксится к payload при сборке
examples/hello/         минимальный пример пакета
tests/{lint.sh,e2e.sh}  shellcheck + жизненный цикл
```

Принцип: один модуль — одна ответственность. Детект платформы, вывод и строки — каждый в одном месте,
не размазаны (в отличие от оригинала с тройным дублированием арх-`case` и 130 строковыми глобалами).

## Поток сборки (`bs build`, lib/pack.sh)

1. Разобрать аргументы (`<src>`, `-o`, `--gzip`).
2. `manifest::parse` + `manifest::validate` (обязательные поля, безопасное имя).
3. Проверить, что `exec` существует в исходнике. Бандлинг (если включён) требует нативной арх.
4. Скопировать исходник в staging (`mktemp`, не мутируя оригинал; права и симлинки сохраняются;
   артефакты сборки исключаются). Выставить exec-бит.
5. Опц. `bundle::collect`: `ldd` -> копировать не-системные `.so` в `staging/lib`.
6. Упаковать staging в `tar.xz` (фолбэк `gzip`). Члены — в корне архива (без `./`).
7. `cat template/stub.sh + payload > out.bs`, `chmod +x`. Опц. `sha256` рядом.
8. Очистка temp по `trap ... EXIT`.

## Поток раннтайма (template/stub.sh — внутри каждого `.bs`)

Stub самодостаточен: package работает только с coreutils + tar (+ xz/gzip).

1. Найти payload по строке-маркеру `__BS_PAYLOAD__` (первое полное совпадение), `tail -n +N`.
2. Определить сжатие по magic-байтам (`fd37…` xz, `1f8b` gzip) и распаковать **явно** —
   этот tar не автодетектит сжатие из пайпа.
3. Прочитать встроенный `manifest` (только нужный член через `tar -xO`), распарсить как данные.
4. Режим:
   - **run** (дефолт): распаковать в XDG-кэш идемпотентно, выставить `PATH`/`LD_LIBRARY_PATH`,
     опц. `isolate_home`, `exec` приложение;
   - **--install [--system]**: разложить по XDG (user) или `/opt`+`/usr/local` (system),
     сгенерировать лаунчер и `.desktop` из манифеста, записать список путей в `<appdir>/.bs-files`;
   - **--uninstall**: прочитать `.bs-files`, удалить, снести каталог приложения;
   - **--extract / --info / --help**.

## Как расширять

- **Новая строка UI:** добавь ключ в `locales/en.sh` (и `ru.sh`), используй `i18n::t key [args]`.
  Английский — обязательная база; недостающий перевод мягко падает в английский.
- **Новая платформа (например, FreeBSD):** добавь `lib/platform/freebsd.sh` с теми же функциями,
  что и `linux.sh`. Не вставляй `if FreeBSD` в тело других функций.
- **Новое поле манифеста:** опиши в [`docs/PACKAGE-FORMAT.md`](PACKAGE-FORMAT.md); парсер
  принимает неизвестные ключи (forward-compat), читай через `BS_MANIFEST[key]` / `MF[key]`.
- **Перед PR:** прогони `tests/lint.sh` (shellcheck) и `tests/e2e.sh`.
